# 🧪 Automated E-Commerce UI Test Suite — PiterGSM

Учебный проект по автоматизации тестирования интернет-магазина **PiterGSM**.

Проект представляет собой набор автоматизированных **UI / E2E-тестов**, написанных на Python с использованием **Pytest и Selenium WebDriver**.

Для организации тестов применяется паттерн **Page Object Model (POM)**, позволяющий разделить тестовую логику, элементы страниц и вспомогательные функции.

Проект создан для практики автоматизации тестирования веб-приложений и демонстрирует подход к построению поддерживаемого автотестового фреймворка.

---

## 🎯 Цель проекта

Основная задача проекта — автоматизировать проверку ключевых пользовательских сценариев интернет-магазина.

В рамках проекта реализованы проверки:

* переходов между страницами;
* поиска и выбора товаров;
* работы с карточками товаров;
* добавления товаров в корзину;
* проверки содержимого корзины;
* оформления заказа;
* взаимодействия с элементами интерфейса;
* позитивных и негативных сценариев.

Тесты построены таким образом, чтобы основные действия пользователя можно было воспроизводить автоматически и получать подробную информацию о результатах выполнения.

## 🏗 Архитектура проекта

В проекте используется паттерн **Page Object Model (POM)**.

Каждая страница приложения представлена отдельным Python-классом, содержащим:

* локаторы элементов;
* методы взаимодействия с элементами;
* действия пользователя на странице.

Благодаря этому тесты содержат преимущественно бизнес-логику сценария и не зависят напрямую от реализации HTML-страницы.

Пример:

```text
Test
  ↓
Page Object
  ↓
Selenium WebDriver
  ↓
Web Application
```

Такой подход упрощает поддержку тестов при изменении интерфейса приложения.

## 🚀 Быстрый старт

### 1. Клонирование репозитория

```bash
git clone https://github.com/norwgwoods-iti/TestPiterGsm.git
cd TestPiterGsm
```

### 2. Установка uv

Проект использует **uv** для управления виртуальным окружением и зависимостями.

После установки uv создайте окружение:

```bash
uv venv
```

Активируйте виртуальное окружение.

### macOS / Linux

```bash
source .venv/bin/activate
```

### Windows

```bash
.venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
uv sync
```

После установки зависимостей проект готов к запуску.

# 📊 Allure Report

Для визуализации результатов тестирования используется **Allure Framework**.

## 1. Запуск тестов с сохранением результатов

```bash
pytest --alluredir=allure-results
```

или:

```bash
uv run pytest --alluredir=allure-results
```

После выполнения тестов в директории `allure-results` будут сохранены данные для формирования отчёта.

---

## 2. Просмотр отчёта

Для запуска локального Allure Report:

```bash
allure serve allure-results
```

После выполнения команды Allure автоматически сформирует отчёт и откроет его в браузере.

Для остановки локального сервера:

```text
Ctrl + C
```

---

## 3. Генерация статического отчёта

Если необходимо создать полноценную директорию с HTML-отчётом:

```bash
allure generate allure-results -o allure-report --clean
```

После этого отчёт будет находиться в:

```text
allure-report/
```

## 📂 Назначение директорий

### `base/`

Базовые классы, используемые Page Object'ами.

`base_class.py` содержит общую функциональность для работы с WebDriver, логированием и вспомогательными действиями.

### `pages/`

Page Object классы.

Каждый класс соответствует определённой странице или разделу интернет-магазина:

* `main_page.py` — главная страница;
* `mac_page.py` — раздел Mac;
* `imac_page.py` — карточка товара iMac;
* `audio_page.py` — раздел аудиотоваров;
* `headphones_page.py` — страница наушников;
* `cart_page.py` — корзина;
* `order_page.py` — оформление заказа.

### `tests/`

Автоматизированные тестовые сценарии.

Здесь также находится:

```text
conftest.py
```

который используется для настройки Pytest fixtures и управления жизненным циклом WebDriver.

### `utilities/`

Вспомогательные модули проекта.

Например:

```text
logger.py
```

отвечает за логирование выполнения тестов.

### `screen/`

Директория для сохранения скриншотов.

### `logs/`

Директория для файлов логирования выполнения тестов.

# 🔍 Пример тестового сценария

Один из основных сценариев проекта — проверка пользовательского пути покупки товара.

Упрощённо сценарий выглядит следующим образом:

```text
Открыть интернет-магазин
        ↓
Перейти в каталог
        ↓
Выбрать категорию товара
        ↓
Открыть карточку товара
        ↓
Добавить товар в корзину
        ↓
Перейти в корзину
        ↓
Проверить наличие товара
        ↓
Перейти к оформлению заказа
        ↓
Проверить результат
```

Все действия выполняются автоматически через Selenium WebDriver.

# 🧩 Принципы автоматизации

В проекте используются следующие подходы:

* **Page Object Model** — отделение логики страниц от тестов;
* **Pytest fixtures** — управление тестовым окружением;
* **явные ожидания Selenium** — ожидание готовности элементов перед взаимодействием;
* **разделение тестов и вспомогательной логики**;
* **логирование действий**;
* **сохранение артефактов выполнения**;
* **Allure Report** для анализа результатов тестирования.
